# PV016 — DeepSeek nested core risk extraction

Analyze only the supplied Form 10-K Item 1A packet. Identify exactly three distinct material risks using severe or broad consequences explicitly stated by the filer. Do not use outside knowledge, search, or unstated facts.

Return one JSON object only. The top level must contain exactly `case_id`, `model_id`, `prompt_version`, and `risks`. Copy the harness metadata strings exactly. `risks` must contain exactly three objects ordered `R1`, `R2`, `R3`.

Every risk object must contain all of these fields with these JSON types:

- strings: `risk_id`, `risk_summary`, `risk_type`, `evidence_quote`, `reasoning`, `financial_impact`, `time_horizon`, `mitigation`, `uncertainty`
- array of strings: `source_paragraph_ids`, `monitoring_indicators`
- array of integers: `source_pages`

Never use singular `paragraph_id` or `pdf_page`. Never place risk-analysis fields at the top level.

For each risk, copy a 5–18 word `evidence_quote` from one physical input line without merging lines or changing any character or punctuation. Put the governing `[PARAGRAPH ...]` value inside the `source_paragraph_ids` array and the nearest preceding integer `[PDF_PAGE ...]` inside the `source_pages` array. Use only the locator needed for that quote.

Classify the primary driver rather than its downstream consequence: market demand, competition, asset prices, adoption, and strategic partnerships are `Strategic / Market / Technology`; operational service dependencies and disruptions are `Operational / Supply Chain`; laws and enforcement are `Regulatory / Legal / Geopolitical`; liquidity, credit, lending, funding, and counterparty default are `Financial / Liquidity / Credit`; security, data, privacy, access, and breaches are `Cybersecurity / Data / Privacy`; otherwise use `Other`.

Inside every risk object, set `reasoning`, `financial_impact`, `time_horizon`, `mitigation`, and `uncertainty` exactly to `Not separately analyzed in the core extraction task.` and set `monitoring_indicators` to `[]`.
